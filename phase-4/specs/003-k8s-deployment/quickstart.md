# Quickstart Guide: Containerize and Deploy Todo Chatbot to Minikube

## Overview
This guide provides a rapid path to containerize and deploy the Phase 3 Todo Chatbot to a local Minikube cluster using Docker, Helm, and kubectl-ai. This implementation strictly follows the constitutional requirement to use designated Phase 4 skills for all operations.

## Prerequisites
- Minikube installed and running
- Docker installed and running
- kubectl installed
- kubectl-ai plugin installed
- kagent installed
- Helm installed
- Phase 4 skills available (Docker Containerization, Helm Chart Generation, Minikube Local Deployment Orchestration, Infrastructure Spec Validation)

## Quick Steps

1. **Prepare Environment**
   ```bash
   minikube start
   eval $(minikube docker-env)  # If using Minikube's Docker daemon
   ```

2. **Generate Dockerfiles** (using Docker Containerization skill)
   ```bash
   # Invoke the Docker Containerization skill to generate multi-stage Dockerfiles
   # The skill will create optimized Dockerfiles for both frontend and backend
   # Output will be stored in docker/frontend/Dockerfile and docker/backend/Dockerfile
   ```

3. **Build Docker Images**
   ```bash
   # Use the generated Dockerfiles to build images
   docker build -t todo-frontend:latest -f docker/frontend/Dockerfile .
   docker build -t todo-backend:latest -f docker/backend/Dockerfile .
   ```

4. **Generate Helm Chart** (using Helm Chart Generation skill)
   ```bash
   # Invoke the Helm Chart Generation skill to create a complete Helm chart
   # The skill will generate charts/todo-chatbot/ with proper templates and values
   # Ensuring separate deployments for frontend and backend with configurable values
   ```

5. **Validate Infrastructure** (using Infrastructure Spec Validation skill)
   ```bash
   # Run validation on the generated Helm chart before deployment
   # Ensures compliance with constitutional requirements
   ```

6. **Deploy with Helm**
   ```bash
   helm install todo-chatbot ./charts/todo-chatbot --wait --timeout=10m
   ```

7. **Verify Deployment**
   ```bash
   kubectl get pods
   kubectl get services
   kubectl get deployments
   minikube service todo-frontend-service --url  # Get frontend URL
   ```

8. **Access Application**
   ```bash
   # Open the frontend URL in your browser
   # Or use curl to test the backend API
   curl $(minikube service todo-backend-service --url)/health
   ```

## Configuration Options

### Resource Constraints
The deployment enforces constitutional resource limits:
- CPU: < 500m per container
- Memory: < 512Mi per container
- Configure via values.yaml in the Helm chart

### Dapr Integration
Dapr annotations are prepared for Phase 5:
- Enable via Helm value: `--set dapr.enabled=true`
- Configure via values.yaml in the Helm chart

## Troubleshooting

### Common Issues
1. **Images not building**: Ensure Dockerfiles were generated by the Docker Containerization skill
2. **Service not accessible**: Check that Minikube is running and use `minikube service` command
3. **Resource limits exceeded**: Verify that your deployment complies with constitutional limits

### Verification Commands
```bash
# Check all resources
kubectl get all

# Check pod status
kubectl get pods -o wide

# Check service endpoints
kubectl get svc

# View logs
kubectl logs deployment/todo-frontend
kubectl logs deployment/todo-backend
```
